# scripts/

Shared code and CLIs for the source-side ingest tooling, the runtime/composition harness, and the bridge between them. This directory is indexed from the functional layer at [docs/functional/README.md](../docs/functional/README.md).

## Modules

- [source_ingest.py](source_ingest.py) — source-side ingest and review CLI: family inspection, source-layout detection, source-cell lookup, semantic review-pack export, collection review-pack export, and ingest/audit checks. Use this when the task starts from a raw sheet or reference image rather than from a composed scene. This is the CLI entrypoint; the operator function bodies live in `source_ingest_ops.py`.
- [source_manifests.py](source_manifests.py) — staged source-side pack / tileset / logical-tilesheet manifest loader and validator for the current ingest model. This module is intentionally ingest-only; the runtime should continue to consume compatibility/library units rather than these manifests directly.
- [source_manifest_bridge.py](source_manifest_bridge.py) — one-way transitional adapter from the staged source manifests into the current family-backed compatibility pipeline. Keeps source-side module identity, module context, render traits, and documented hints explicit while promoting the runtime-relevant subset onto the `TileFamily` / `TileLibraryUnit` boundary.
- [reference_grid.py](reference_grid.py) — reference-sheet slicing helper: apply a solved render-grid transform to a screenshot/reference image, optionally trim it to one or more relevant tiled regions, keep or drop partially visible edge cells, then emit a full-cell crop and padded guide overlays for tile-by-tile review. An optional recovered-tile matcher-debug sheet is available explicitly when low-level tile recovery needs inspection, but it is no longer part of the default review output set.
- [reference_tile_match.py](reference_tile_match.py) — reference-tile matcher: compare recovered reference cells against one or more candidate source sheets, with the same relevant-region and exclusion-box controls as the slicer, reporting blank cells, exact matches, tiered guessed matches, and optional manual review overrides.
- [harness.py](harness.py) — runtime/composition harness CLI: the scene-runtime + entity-resolution layer (scene-template expansion, entity placement, parametric run/frame expansion), the layout render pipeline, project bootstrap, and the CLI command dispatch. Depends on `layout_core` and `source_ingest_ops`.
- [layout_core.py](layout_core.py) — the shared base layer: `LayoutProject`, the project/layout config + tile data types (`ResolvedTile`, `Pattern`, `TileRenderSpec`, `GridTileset`, `TileFamilySelection`), and the render/draw/geometry primitives + loaders. Imports only upstream modules; consumed by both the harness and the source-ingest operators.
- [source_ingest_ops.py](source_ingest_ops.py) — the operator layer: the inspect / export / audit / validate / detect functions (and their helpers) that turn a loaded family + project into review packs, public tile packs, Tiled kits, catalogs and diagnostics. Depends on `layout_core`; invoked by the `source_ingest.py` CLI.
- [tile_families.py](tile_families.py) — generic tile-family ingest, loader and query model: family / cluster / tile catalogs, alias resolution, address parsing, construction loading and validation, source-layout, and detection/bootstrap.
- [tile_library.py](tile_library.py) — the runtime library surface consumed after load: the construction records (`FixedConstruction` / `ParametricRunConstruction` / `ParametricFrameConstruction`), tile / cluster records, and the catalog containers `TileLibraryUnit` (a self-contained runtime-facing view with promoted runtime metadata) and `TileLibraryRegistry` (the registry over loaded units). The dependency runs one-directional, ingest (`tile_families`) → library (`tile_library`).
- [tile_normalisation.py](tile_normalisation.py) — shared transparency-normalisation primitive (background keying), used by both the renderer (`layout_core`) and runtime seam derivation (`tile_families`) so the rule lives once. Pure PIL; imports nothing from our own layers.
- [seam_profiles.py](seam_profiles.py) — pure seam-profile derivation core: per-side occupancy mask of a tile's 1px contact line from a boolean occupancy grid (ADR 0007 mechanical axis). PIL-free.
- [seam_matching.py](seam_matching.py) — composable, pure seam matchers (`equality` for butt-joins, `complement` for interlocking joins) under a config-driven `MatchPolicy`; the unit of graded comparison for seam fit.
- [scene_templates.py](scene_templates.py) — scene template DSL: file-backed loading, validation, expression evaluation, data-mode scene expansion, cycle detection across `place_scene`.
- [scene_rules.py](scene_rules.py) — environment-specific scene-rules loader and validator for weighted stamp/entity/scene candidate catalogues.
- [prototype_output.py](prototype_output.py) — render pipeline output helpers (staged writes, archive rotation on diff).

## Tooling

- [check_pyright.sh](check_pyright.sh) — type-check entrypoint. Required to pass before committing typed engine changes.
- [check_coverage.sh](check_coverage.sh) — coverage entrypoint for the shared Python scripts.
- `python3 scripts/source_ingest.py --help` — source-side review and ingest entrypoint. Use this for family inspection, source-layout detection, source-sheet cell lookup, review-pack export, and ingest/audit validation.
- `python3 scripts/source_ingest.py inspect-family prototypes/minimal8-harness/project.minimal8.json --tileset 'minimal8@2bit_colored_bg'` — export the source-sheet inspection bundle for one family variant. When the family has a committed source-layout map, this also writes `source_layout.json`, `source_layout.png`, and `source_layout.guide.png`: a numbered zero-based source-sheet guide with the committed source regions, clusters, ignores, and collections overlaid on the real sheet art.
- `python3 scripts/source_ingest.py inspect-source-cell prototypes/minimal8-harness/project.minimal8.json --tileset 'minimal8@2bit_colored_bg' --sheet-col 21 --sheet-row 4` — inspect one zero-based source-sheet cell through the authoritative ingest map. This is the safest way to answer “what is the third tile from the left in the top section of the second source-sheet column?” because it reports the source-layout region/cluster context and any mapped family tile in one place instead of forcing you to infer that join from ad hoc review sheets.
- `python3 scripts/reference_grid.py --help` — extract a reference image onto a stable tile grid once you know either the render-space origin/cell size or the exact tiled-body `span_box`; optionally normalize that raw span onto a uniform cell size for matching/review, constrain the solve to relevant tiled regions, ignore headings or other excluded zones, decide whether partially visible edge cells stay in the ingested sheet, choose between `separated` (default) or `overlay` guide-line rendering, and optionally use `--transparent-grid-surface` when you want only the grid content area transparent while keeping the outer guide chrome filled. If you are debugging matcher internals rather than reviewing the scene visually, `--emit-recovered-tile-sheet` also exports the recovered canonical tile surface as an explicit matcher-debug artefact.
- `python3 scripts/reference_tile_match.py --help` — match extracted reference cells against one or more candidate source sheets once the grid transform is known, using the same origin/pitch-or-span solve model plus the same optional normalized ingest surface, relevant-region controls, and exclusion controls as the slicer. The matcher now classifies cells as `blank`, `exact`, `high_confidence`, `best_guess`, or `unresolved`, records config-driven `reviews` separately from machine confidence, and reports both raw `mask_iou` and a conservative trimmed logical-mask rescue for reference cases where the motif is right but whitespace placement inside the cell has drifted. Multi-source configs also preserve per-candidate provenance (`source_id`, `family_id`, `variant_id`, `sheet_col`, `sheet_row`), emit copy-pasteable `physical_ref` / `variant_ref` / `semantic_variant_ref` strings, expose the loaded source colourways, can constrain a source to specific `reference_boxes`, and let review overrides confirm either a semantic `tile_id` or a raw `source_cell`, optionally pinned to a specific `variant_id`. For reconstruction workflows, each exact/candidate match also carries a sibling-colourway recommendation (`recommended_variant_id`, `recommended_variant_ref`, `recommended_semantic_variant_ref`) chosen after identity matching by comparing the reference cell's foreground colours against the same sheet cell across sibling variants.
- Both tools also accept `--config <json>` so committed reference-ingest state can live in repo and be rerun without retyping the transform. Current Minimal 8 examples live at [prototypes/minimal8-harness/reference-transforms/reference-overworld-island-title-screen.json](../prototypes/minimal8-harness/reference-transforms/reference-overworld-island-title-screen.json) and [prototypes/minimal8-harness/reference-transforms/reference-polychrome-temple-courtyard.json](../prototypes/minimal8-harness/reference-transforms/reference-polychrome-temple-courtyard.json). [reference-party-menu-character-stats.json](../prototypes/minimal8-harness/reference-transforms/reference-party-menu-character-stats.json) is now the canonical reviewed handoff for that screen: the trusted grid solve plus the reviewed tile-and-colour truth, with one explicit intentional recreation deviation at `C31R17`. The slicer also saves the trimmed ingest guide beside the source image with a `--guide` suffix and, when normalization is enabled, writes `*_normalized_body.png` plus the same ingest-sheet overlays into the chosen output directory so the solved sheet can be reused during manual ingest or scene reconstruction.
