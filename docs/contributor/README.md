# Contributor Documentation

This layer is the home for everyone working in the repo — humans and agents both. The bootstrap ([AGENTS.md](../../AGENTS.md)) routes you here; everything you need to know about *how* to contribute lives in this layer.

## Layer artefacts

- [documentation-standard.md](documentation-standard.md) — which documentation standard the repo follows, current maturity level, and the obligations on every change.
- [repo-structure.md](repo-structure.md) — repo layout, ownership rules for generated outputs, scratch conventions, LFS policy.
- [working-rules.md](working-rules.md) — code design, canonical sources of truth, review workflow, change discipline, verification, commit conventions.
- [changelog-standard.md](changelog-standard.md) — how versioned release history is recorded in `docs/CHANGELOG.md` and `docs/changelog/vX.Y.Z.md`.
- [commit-messages.md](commit-messages.md) — how commit history stays scannable and how versioned commit subjects line up with changelog Summaries.
- [CONTRIBUTING.md](../../CONTRIBUTING.md) — public-facing contributor landing page (per the agent-ready documentation standard's convention-based exception). Carries the baseline pointers and links back here for the full set.

## Where to start

- New to the repo? Read [repo-structure.md](repo-structure.md) first, then [working-rules.md](working-rules.md).
- Touching documentation? Read [documentation-standard.md](documentation-standard.md) so you know the rules before you change them.
- Shipping a version? Read [changelog-standard.md](changelog-standard.md) and [commit-messages.md](commit-messages.md).
- Touching engine code? Read [working-rules.md](working-rules.md) for the design / verification expectations.
