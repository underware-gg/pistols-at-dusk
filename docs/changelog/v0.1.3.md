# v0.1.3 — 2026-05-18

**Introduce a tile library registry**

v0.1.3 adds a tile library registry alongside the runtime boundary from v0.1.2. The registry is the entry point through which the harness obtains tile libraries by name; the boundary stays the same, but resolution now goes through a registered lookup rather than a direct loader call.

- A registry object lets callers register tile libraries by name and resolve them at runtime. The harness routes its loader through the registry so subsequent work can support multiple registered libraries.
  - Important identifiers: `scripts/tile_families.py`, `scripts/minimal8_harness.py`
- New behavioural tests pin the registry contract: registration, lookup, and the harness wiring that consumes it.
  - Important identifiers: `tests/test_tile_families.py`
- Architecture, functional, and scripts indexes are updated to name the registry so contributors can find it.
  - Important identifiers: `docs/architecture/README.md`, `docs/functional/README.md`, `scripts/README.md`
