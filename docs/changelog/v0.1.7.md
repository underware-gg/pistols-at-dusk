# v0.1.7 — 2026-05-19

**Bridge staged source packs into family-backed loading**

v0.1.7 turns the Phase 4 source-pack hierarchy into the active project entrypoint by routing staged packs through the current `TileFamily` compatibility path and migrating Minimal 8 onto that bridge.

- Staged source packs now adapt into the current family-backed compatibility pipeline through a one-way bridge that validates staged metadata against legacy compatibility bundles while keeping runtime consumption on `TileFamily`, `TileLibraryUnit`, and `TileLibraryRegistry`.
  - Important identifiers: `scripts/source_manifest_bridge.py`, `scripts/compatibility_family.py`, `scripts/tile_families.py`, `tests/test_source_manifest_bridge.py`
- The Minimal 8 harness and committed prototype fixtures now load from `tile_family.source_pack` and staged pack manifests instead of pointing projects straight at the legacy family directory.
  - Important identifiers: `scripts/minimal8_harness.py`, `prototypes/minimal8-harness/project.minimal8.json`, `prototypes/minimal8-harness/project.minimal8.2bit.json`, `prototypes/minimal8-harness/tile-packs/minimal8/`
- Source-manifest, harness, and scene-expansion verification now pin the symmetric fallback and equivalence rules that keep the staged bridge honest during the transition.
  - Important identifiers: `scripts/source_manifests.py`, `tests/test_source_manifests.py`, `tests/test_minimal8_harness.py`, `tests/test_scene_expansion.py`
- Functional, user, and architecture docs now describe staged source packs as the active Minimal 8 entrypoint while keeping the legacy family package documented as the transitional compatibility bundle.
  - Important identifiers: `docs/user/README.md`, `docs/functional/README.md`, `docs/architecture/README.md`, `docs/architecture/source-sheet-ingestion-model.md`, `prototypes/minimal8-harness/README.md`, `scripts/README.md`
