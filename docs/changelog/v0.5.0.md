# v0.5.0 — 2026-05-30

**Split tile_library off ingest and normalise ingest signatures**

v0.5.0 draws a clean ingest/runtime boundary by extracting the runtime library
surface out of `scripts/tile_families.py` into a new `scripts/tile_library.py`,
and normalises the seven source-ingest functions onto single `LayoutProject`
signatures. Both moves are breaking: the runtime symbols relocate with no
re-export shim, and the redundant `project_path` positional plus `project=`
escape hatch are removed, so importers and callers must repoint.

- The runtime library surface now lives in its own module, with the dependency
  running one-directional (ingest -> library): the construction records, tile/
  cluster/sheet/resolved records, the catalog protocol and containers move to
  `scripts/tile_library.py`, `TileLibraryUnit.from_family` is inverted into
  `TileFamily.runtime_unit`, and `resolve_tile_image_override_path` is promoted
  to a shared public helper. There is no re-export shim, so importers repoint at
  the defining module.
  - Important identifiers: `scripts/tile_library.py`, `scripts/tile_families.py`, `MetatileConstruction`, `ParametricRunConstruction`, `ParametricFrameConstruction`, `TileRecord`, `RuntimeConstructionCatalog`, `TileLibraryUnit`, `LoadedTileLibraryUnit`, `TileLibraryRegistry`, `resolve_tile_image_override_path`
- The seven source-ingest functions now take a single `LayoutProject` as their
  first argument, dropping the dual `(project_path, *, project=None)` signature
  and the `project = project or LayoutProject(...)` resolution line; the
  `source_ingest.py` CLI builds the project once and passes it straight through,
  and report payloads use the canonical resolved `project.project_path`.
  - Important identifiers: `scripts/minimal8_harness.py`, `inspect_family`, `detect_family_source_layout`, `inspect_source_cell`, `export_semantic_review_pack`, `export_collection_review_pack`, `validate_family_ingest`, `audit_family_semantic_usage`, `scripts/source_ingest.py`, `scripts/source_manifest_bridge.py`
- The boundary now carries durable guard and coverage tests: one asserts the
  runtime `TileLibraryUnit` never exposes the ingest-only `source_layout`
  attribute that the ingest `TileFamily` still carries, and the other exercises
  the entity-op `variant_id` pipeline end to end so placement refs are prefixed
  with the chosen variant's runtime tileset id.
  - Important identifiers: `tests/test_tile_families.py`, `test_runtime_unit_omits_source_layout_ingest_attribute`, `tests/test_scene_expansion.py`, `runtime_tileset_id_for_construction`, `_resolve_scene_entity_request`
- The contributor and architecture docs now name the two-module split and its
  one-directional ingest -> library dependency, so new contributors read the
  seam where it now lives instead of the old all-in-`tile_families` layout.
  - Important identifiers: `docs/architecture/README.md`, `docs/contributor/repo-structure.md`, `docs/contributor/working-rules.md`, `docs/functional/README.md`
