# v0.1.5 — 2026-05-18

**Route family references across loaded tile libraries**

v0.1.5 closes the multi-unit arc started in v0.1.3 and v0.1.4 by routing family references across every registered tile library. Project configuration can now name a family by reference and the registry will resolve it against the right loaded library, with the routing surface narrowed to a single resolver.

- Family references are resolved through a single registry-level routing surface that walks the registered libraries and returns the owning unit; the harness consumes that surface in place of per-library lookups.
  - Important identifiers: `scripts/tile_families.py`, `scripts/minimal8_harness.py`
- An architecture decision record captures the choice to let the runtime registry hold multiple compatibility units and route refs across them.
  - Important identifiers: `docs/architecture/decisions/0004-runtime-registry-loads-multiple-compatibility-units.md`, `docs/architecture/decisions/README.md`
- Behavioural tests pin the routing contract: cross-library resolution, ambiguity handling, and the harness flows that consume the resolver.
  - Important identifiers: `tests/test_tile_families.py`, `tests/test_minimal8_harness.py`
- Architecture and functional indexes are updated so the routing surface is documented alongside the registry and multi-load work.
  - Important identifiers: `docs/architecture/README.md`, `docs/functional/README.md`
